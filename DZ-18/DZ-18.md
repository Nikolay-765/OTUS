# ДЗ № 18
## Тема: "Резервное копирование"
Задание: 
1. Настроить стенд Vagrant с двумя виртуальными машинами: backup_server и client.
2. Настроить удаленный бекап каталога /etc c сервера client при помощи borgbackup. Резервные копии должны соответствовать следующим критериям:
- директория для резервных копий /var/backup. Это должна быть отдельная точка монтирования. В данном случае для демонстрации размер не принципиален, достаточно будет и 2GB;
- репозиторий дле резервных копий должен быть зашифрован ключом или паролем - на ваше усмотрение;
- имя бекапа должно содержать информацию о времени снятия бекапа;
- глубина бекапа должна быть год, хранить можно по последней копии на конец месяца, кроме последних трех.
- резервная копия снимается каждые 5 минут (частый запуск в целях демонстрации);
- написан скрипт для снятия резервных копий. Скрипт запускается из соответствующей Cron джобы, либо systemd timer-а - на ваше усмотрение;
- настроено логирование процесса бекапа.
3. Запустить стенд на 30 минут.
4. Убедитесь что резервные копии снимаются.
5. Остановите бекап, удалите (или переместите) директорию /etc и восстановите ее из бекапа.

## Подготовка 
Поднимаются 2 MV с ОС Ubuntu 24.04:
- backup (IP: 192.168.60.150), имеется домолнительный лиск на 2 Gb, который монтируется в /var/backup, на VM дополнительно стявятся: borgbackup и sshfs
- client (IP: 192.168.60.160)

Vagrant: 
- конфигурационный файл [Vagrantfile](./Files/Vagrantfile)
  
Ansible (файлы-сценарии должны лежать в директории ./Provisioning относительно файла Vagrantfile):
- основные сценарии [backup.yml](./Files/backup.yml), [client.yml](./Files/client.yml)
- сценарий настройки внешнего диска для VM backup [disk_prepare.yml](./Files/disk_prepare.yml) 

Вorgbackup работает через SSH по push схеме. При таком раскладе необходимо будет организовать доступ с клиента по ключу \
на backupserver, что не очень здорово с точки зтения безопасности. Чтобы обойти это ограничение используется утилита sshfs, \
которая позволяет монтировать на VM backup как диск целевую диретрорию с VM client. \
Далее backup снивается с указанного диска "локально". \
При этом SSH соединение пробрасывается с backup на client. И возможность подключения с client на backup c авторизацией по ключу не предустатривается.

## Выполнение задания 
1. Обеспечиваем рутовый доступ c VM backup на VM client по SSH по ключу.
На VM backup cоздаем пару RSA ключей \
Открытый ключь прописываем на VM client в /root/.ssh/authorized_keys 
2. Готовим скрипты для работы с borgbackup (скрипты размещаются в /usr/local/bin)
- [init_backup_repo.sh](./Scripts/init_backup_repo.sh) - инициализация репы под бэкапы
- [make_backup.sh](./Scripts/make_backup.sh) - создание бэкапа
- [restore_from_backup.sh](./Scripts/restore_from_backup.sh) - восттановление данных из бэкапа
3. Готовим файлы для организации автоматического съема бэкапов (с помощью systemd), при этом запись логов ведется systemd-journald
- [borg-backup.service](./Service/borg-backup.service) - системная служба (для репы задан пароль: qwerty )
- [borg-backup.timer](./Service/borg-backup.timer) - таймер, запускает borg-backup.service каждые 5 минут (после первого старта)
4. Устанавливаем все это хозяйство на стенд и тестируем
Смотрим как это работает:
```
root@backup:/tmp# systemctl list-timers borg-backup
NEXT                            LEFT LAST                             PASSED UNIT              ACTIVATES          
Wed 2026-07-22 12:14:29 UTC 2min 58s Wed 2026-07-22 12:09:29 UTC 2min 1s ago borg-backup.timer borg-backup.service

1 timers listed.
Pass --all to see loaded but inactive timers, too.

root@backup:/tmp# borg list /var/backup
Enter passphrase for key /var/backup: 
192.168.60.160-etc-2026-07-22_10:56:37 Wed, 2026-07-22 09:56:37 [ea5e9c8a457c87fb42a12097ee64784650eb8c55d0a74cbd52c1dae96c0dd446]
192.168.60.160-etc-2026-07-22_12:09:29 Wed, 2026-07-22 12:09:30 [c4c2eb04b476bd58a96d2b538e7ac1ddddd98d8adfba9d50623314bd6f720a7e]
```
С посощью journalctl смортим логи: [log.txt](./Logs/log.txt) \
Останавливаем таймер (borg-backup.timer) \
Сносим на VM client в целевой папке контрольную директорию /etc/test \
С помощью скрипта restore_from_backup.sh восстанавливаемся из последнего бэкапа
```
./restore_from_backup.sh /var/backup 192.168.60.160-etc-2026-07-22_12:09:29 root@192.168.60.160:/etc
```
В результате данные в целевой папке, в том числе директория /etc/test со всем содержимым восстановлены.

Все работает.
